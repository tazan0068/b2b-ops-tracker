# 공개 집계 웹앱 (Apps Script) — 설치·운영 안내

로그인 없이 보는 "공개 보기"에 숫자를 공급하는 서버 쪽 구성입니다. **아직 어디에도 배포하지 않았습니다.** 아래 순서는 배포 승인 후 시트 소유자가 진행합니다.

## 무엇을 하나
- 구글시트(25개 탭)를 시트 소유자 권한으로 **읽기만** 합니다. 코드에 쓰기 호출(`setValue`·`appendRow` 등)이 없습니다.
- 10분마다 "시트가 바뀌었는지"만 확인하고, 바뀐 경우에만 집계합니다(하루 1회는 무조건 재집계).
- 집계 결과(연도·기간별 건수·금액·비율, 1.통합KPI, 18.선행지표요약)를 이 스크립트 프로젝트의 **스크립트 속성**에 저장합니다. 드라이브 파일·GitHub·외부 서버·토큰을 쓰지 않습니다.
- 웹앱 주소(`…/exec`)에 접속하면 저장된 집계 JSON 한 가지만 돌려줍니다. 요청 파라미터로 시트의 다른 내용을 읽을 수 없습니다.

## 공개되는 것 / 공개되지 않는 것
| 공개(집계값) | 비공개 |
|---|---|
| 연도별 공고·낙찰 건수, 낙찰금액, 공고 대비 낙찰 비율 | 시공사(거래처)명·통합ID·사업자번호 |
| 전체/메인 자재 매출, 우레탄·페인트·에폭시 매출 | 현장명·주소·적요 |
| 낙찰 시공사 수, 구매 확인 업체 수·비율·금액(합계) | 판매 원문·거래 명세, 거래처별 매출 |
| 공종별 낙찰 건수·금액(공종그룹 단위) | 영업활동 목록, L2→L3 검토 목록 |
| 1.통합KPI(연도별), 18.선행지표요약(숫자 집계) | 연결 후보 목록, 업체 상세 |

## 게시 전 자동 검증 (하나라도 실패하면 새 값을 게시하지 않고 이전 정상 집계 유지)
1. 25개 탭이 모두 있고 열 머리글이 기준 구조와 같다
2. 집계 결과가 기존 1.통합KPI와 모두 일치한다(현재 60개 항목 일치)
3. 판매 원문 행 수가 직전 게시본보다 5% 넘게 줄지 않았다
4. 공개 JSON 안에 시공사·현장명(마스터·공고·낙찰 목록의 이름)이 한 글자도 들어 있지 않다
5. 읽는 도중 시트가 바뀌지 않았다(바뀌면 다음 확인에서 다시)

## 설치 순서 (시트 소유자 · 승인 후)
1. 구글시트 → 확장 프로그램 → Apps Script → **새 프로젝트**(기존 키 방식 `Code.gs`와 섞지 않기).
2. 프로젝트 설정 → "appsscript.json 매니페스트 파일 표시" 체크 → 이 폴더의 `appsscript.json` 내용으로 교체(권한 범위: 이 스프레드시트 + 트리거 관리만).
3. `Code.gs` 전체를 붙여 넣고 저장.
4. (선택) 프로젝트 설정 → 스크립트 속성 → `DENY_WORDS` = 공개되면 안 되는 단어를 쉼표로(예: 내부 계정명). 코드에는 적지 않습니다.
5. 편집기에서 `refreshPublic` 실행 → 권한 승인 → 로그에서 결과 확인(`published`).
6. `installTriggers` 실행(`TICK_MINUTES`=10분마다 확인 + 매일 05시 재집계). 설치 10분 뒤 `showStatus` 로 `checkedAt` 이 갱신되는지, 편집기 왼쪽 "실행" 기록에서 1회 소요 시간을 확인하세요(개인 계정은 트리거 총 실행 시간 하루 약 90분 — 1회가 길면 `TICK_MINUTES` 를 15~30 으로).
7. 배포 → 새 배포 → 유형 **웹 앱** → 실행 사용자 **나** → 액세스 **모든 사용자** → 배포 → `…/exec` 주소 복사. ← **이 단계가 "공개 설정"입니다.**
8. 브라우저로 주소를 열어 `schema: "b2b-public-kpi/1"` 로 시작하는 JSON 과 시공사·현장 이름이 없는지 확인.
9. 저장소의 `public-config.json` 에 `{ "url": "…/exec" }` 를 넣고 올리면 사이트가 이 주소에서 집계를 읽습니다(배포 승인 필요).

## 운영
- 상태 확인: 편집기에서 `showStatus` 실행(마지막 확인·게시 시각·해시·상태). 화면의 [검증 정보]에도 같은 내용이 보입니다.
- 즉시 갱신: 편집기에서 `refreshPublicForce` 실행.
- 중단: `removeTriggers` 실행 + 배포 관리에서 웹 앱 배포 보관처리 → 공개가 즉시 끊깁니다(시트는 영향 없음).
- 코드 갱신: 새 `Code.gs` 로 교체 후 **같은 배포의 새 버전**으로 올리면 주소가 유지됩니다.
- 상태 값: `ok` 정상 / `stale` 새 집계 게시 보류(이전 정상 집계 제공, 사유는 상태 메시지에) / `blocked` 게시된 적 없음.

## 알아 둘 점 (실서버 미검증)
- 이 코드는 가짜 시트·가짜 서비스(한도 흉내 포함)로 시험했고 실제 Apps Script 에서는 아직 실행해 보지 않았습니다. 첫 실행에서 실행 시간(판매 원문 32,730행 읽기·집계)과 `…/exec` 응답 속도를 확인해야 합니다.
- 소비자(개인 Gmail) 계정은 트리거 총 실행 시간이 하루 약 90분으로 제한됩니다. 변경 감지로 대부분의 실행은 짧게 끝나도록 설계했지만 실측이 필요합니다.
- 웹 앱 주소를 아는 누구나 집계값을 읽습니다. 그래서 집계값 외에는 코드가 만들지도 저장하지도 않습니다.
